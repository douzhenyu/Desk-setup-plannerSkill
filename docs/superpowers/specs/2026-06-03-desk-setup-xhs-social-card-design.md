# 桌搭 Skill 小红书图文设计

## 目标

为 `desk-setup-planner` 这个 Codex skill 制作一套小红书 3:4 图文，用“AI 桌搭顾问”的产品能力做种草展示。重点不是安装教程，而是让读者理解：这个 skill 可以把模糊的桌搭想法、预算、已有设备和限制条件，收敛成一份可执行的桌搭规划手册。

## 平台与输出

- 平台：小红书 / Rednote
- 比例：3:4
- 尺寸：1080 x 1440
- 页数：6 页
- 格式：PNG
- 输出命名：
  - `output/xhs-01-cover.png`
  - `output/xhs-02-problem.png`
  - `output/xhs-03-inputs.png`
  - `output/xhs-04-options.png`
  - `output/xhs-05-converge.png`
  - `output/xhs-06-handbook.png`

## 受众

- 想改造桌面，但不知道从哪里开始的人。
- 对 AI 工具、Codex skill、效率工作流感兴趣的人。
- 有预算和空间限制，希望得到可执行方案，而不是泛泛灵感图的人。

## 核心主张

一个 AI 桌搭顾问，不是给你堆清单，而是把用途、预算、已有设备、不可变约束和风格偏好，整理成三套候选方案，再收敛成可落地的 Markdown 桌搭规划手册。

## 视觉方向

采用 Guizang Social Card Skill 的 Swiss International 模式。

- 主题：IKB Blue
- 字体气质：Inter / Helvetica / Noto Sans SC
- 版式：严格左对齐、清晰网格、轻字重大标题、编号、流程、矩阵和对比模块
- 颜色：白 / 近白 / 黑 / 灰 / 单一 IKB 蓝强调
- 禁止项：装饰贴纸、渐变光斑、玻璃拟态、混合多种强调色、虚构桌面照片

选择 Swiss 的原因：这是 AI 工具和产品能力展示，重点是“结构化决策”和“流程收敛”。Swiss 的流程图、矩阵、KPI 式信息层级比杂志风更适合表达工具能力。

## 素材策略

- 使用现有 `assets/readme-cover.png` 作为产品证据页素材。
- 不额外抓取版权不明图片。
- 不生成假桌面照片，避免让能力展示变成虚构案例。
- 其余页面使用结构化图形、矩阵、流程和文本层级表达。

## 页面脚本

### 01 封面

- 标题：你的桌搭，不该靠玄学
- 辅助信息：AI DESK SETUP PLANNER / SKILL
- 视觉：大标题 + IKB 蓝强调块 + 5 个能力关键词
- 底部关键词：用途 / 预算 / 约束 / 采购 / 理线
- 目的：一眼建立“桌搭规划可以被系统化”的主张。

### 02 问题页

- 标题：普通建议为什么容易失控
- 内容：
  - 先买东西，再想用途
  - 先看风格，再算预算
  - 先堆设备，再处理理线
  - 忽略不能动的桌子、墙面和已有设备
- 视觉：四宫格问题矩阵，突出“不是缺灵感，是缺决策顺序”。

### 03 输入页

- 标题：它先问 6 个关键问题
- 内容：
  - 从 0 搭建，还是现有改造
  - 主用途排序
  - 总预算
  - 已有且要保留的大件
  - 不可变约束
  - 风格偏好和反感项
- 视觉：纵向流程 / checklist。

### 04 方案页

- 标题：默认给你三套方案
- 内容：
  - A 保守实用：少花钱，先解决核心问题
  - B 均衡推荐：效果、预算、难度折中
  - C 进阶升级：更完整，也更贵更复杂
- 视觉：三列对比卡，强调不是单一路线。

### 05 收敛页

- 标题：不是三选一，可以混搭
- 内容：
  - A 的预算纪律
  - B 的显示器和支架布局
  - C 的灯光或收纳方向
  - 删除不必要模块
  - 保留已有设备
- 视觉：模块组合图，表现从候选方案收敛成最终配置。

### 06 结果页

- 标题：最后得到一份落地手册
- 内容：
  - 需求与约束
  - 采购清单
  - 预算表
  - 暂缓购买项
  - 理线方案
  - 安装步骤
  - 升级路线
- 视觉：使用 `assets/readme-cover.png` 做证据图，配合清单式结果说明。

## 文案语气

- 克制、明确、偏产品说明。
- 不使用夸张保证，比如“必看”“神器”“全网最强”。
- 避免承诺具体品牌、价格、型号一定适合。
- 强调“规格优先、购买前核验、根据约束取舍”。

## 实现约束

- 从 `guizang-social-card-skill/assets/template-swiss-card.html` 复制为任务目录的 `index.html`。
- 只使用 Swiss 模板类和 Swiss recipes，不混用 Editorial 类。
- 每页保持安全边距，文字和关键对象不贴边。
- 中文标题优先缩短，不通过把正文缩到不可读来解决溢出。
- 渲染后检查所有 PNG 尺寸是否为 1080 x 1440。
- 使用 `validate-social-deck.mjs` 做自动检查，失败项必须修复，警告项逐项判断。

## 验收标准

- 6 张小红书 PNG 均成功导出。
- 封面在手机缩略图下仍能读出主标题。
- 每页只有一个核心信息点。
- 视觉系统统一：同一网格、同一色板、同一页码/元信息格式。
- 没有文字溢出、页脚碰撞、过小正文、截图变形或裁切错误。
- 最终回复展示封面和至少 1-2 张代表性内容页，并给出输出目录。
